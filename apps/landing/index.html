#Four surfaces, one record

Your work lives in four kinds of artifact, in one workspace. Agents reach them through MCP tools, the CLI or the API, and what one agent makes, the next can read and build on.

#Nothing happens off the tape

Each step an agent takes is stamped on its run, along with the surface it touched. When the run ends, the tape stops and waits for a person. Approve it or reject it, and the record stays.

#Connect your agent

Add one MCP server, and your agent can read and edit the artifacts you do, pick up issues you delegate, and leave a record you can read later.

  • Any agent, one workspace. Claude Code, Codex and your own scripts use the same tools.
  • Live, like Figma. You see the agent's cursor and status while it works.
  • On your machine. The tools talk to your server on localhost.
Claude Code: Terminal
claude mcp add stdartifacts -e STDARTIFACTS_URL=http://localhost:4747 -- npx stdartifacts mcp

Then ask for something like “make a board that maps out our launch, and a tracker with the first ten tasks”, and watch the board fill in.

Codex: ~/.codex/config.toml
[mcp_servers.stdartifacts]
command = "npx"
args = ["stdartifacts", "mcp"]
env = { STDARTIFACTS_URL = "http://localhost:4747" }

Codex picks the server up on its next start. Other MCP clients that run a command over stdio connect the same way.

Before you connect anything

Is it really free?

Yes. Solo is open source and runs on your machine with npx stdartifacts serve, with no account and no cloud. Cloud, hosted for teams, will be priced per team.

Where does my data live?

Solo keeps your workspace in ~/.stdartifacts on your machine, or wherever --data points. The agents you connect read it through MCP, like any other tool they use.

Which agents can connect?

Claude Code, Codex and your own scripts connect over local MCP, the CLI or plain HTTP. Other MCP clients that run a command over stdio connect the same way. ChatGPT and Claude connectors need a public HTTPS server with sign-in, which comes with Cloud.

What gets recorded when an agent works?

While a run is open, each change made through the MCP tools lands on it as a step, and the agent can add its own notes. A run keeps up to 300 steps. Changes made through the CLI aren't logged on a run yet.

Does rejecting a run undo its changes?

No. Reject marks the run as failed and keeps its steps on the record. The changes stay in place until someone edits them, so you can see exactly what to fix.

Can my team use my server?

Not yet. Self-hosting for a team needs sign-in, which isn't built, so a self-hosted server is for one person on localhost. Cloud brings teams, sign-in and roles.

Can I get my data out?

Every artifact reads as plain text over the API, CLI and MCP: rows for tables, shapes for boards, Markdown for docs. There's no one-click export yet.

How is it licensed?

The server, web app and artifact UI are AGPL-3.0-only. The client libraries, MCP server and CLI are Apache-2.0. LICENSING.md explains why.
